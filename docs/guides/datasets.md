# Datasets and semantic maps

> **Audience:** Attack and dataset authors.
>
> **Outcome:** Read scene timelines, recorded states and semantic maps.
>
> **Prerequisites:** [Architecture](../concepts/architecture.md).

## `Dataset` interface

A `Dataset` exposes recorded records or CARLA recipes. It never owns a simulator. Its public
methods list scenarios and frames, read frame data, expose native source records and construct a
`ScenarioStart` for a chosen frame. Mutable return values are independent of cached dataset
reads. See the [Dataset interface](../reference/python-api.md#avsectesterdatasetsbase) for
signatures and validation rules.

`ScenarioStart` carries `scenario_id`, the selected `frame`, `kind` and `payload`, the complete
`recorded_ego` sequence and `scenario_map`. The dataset creates this simulator-independent start
record.

| Record | Purpose |
|---|---|
| `ScenarioDescriptor` | Stable scene identity and provider payload |
| `FrameReference` | Scenario identity, timeline position, native frame ID and timestamp |
| `FrameData` | Recorded ego, other actors, sensor references and provenance |
| `ActorState` | Actor-origin pose, velocity, category, optional extent and local box transform |
| `SensorDataReference` | Native sensor name, payload location, timestamp and decoding metadata |
| `ScenarioStart` | Source payload, recorded ego timeline and semantic map used for reset |
| `Unavailable` | Missing evidence with an explicit reason |

`FrameData.actors` excludes the ego. `FrameData.ego` contains it. Timeline position and native
frame ID are distinct. A window of N decisions needs N+1 supported frame references, including
its terminal state.

`ActorState.pose` is world-from-actor, while `box_center` and `box_rotation` describe the local
box center and orientation. `box_transform()` returns world-from-box-center without changing
the actor origin. Velocity uses world-frame meters per second. Extent is full length, width and
height in meters. An unknown extent is None, distinct from known zero dimensions. Pose-only
operations accept unknown extent. Attached placement and cuboid occlusion require known
dimensions. See [record constraints](../reference/python-api.md#avsectesterdata_types).

CARLA recipes have no recorded ego timeline. Map records are shared as read-only data.
Start payloads are independent copies.

## CARLA recipes

`CarlaDataset` holds named `CarlaRecipe` records. Each recipe supplies actor spawns and
prescribed motion: constant control, per-decision controls or an `ActorState` trajectory. A
recipe includes its terminal state. Prescribed execution follows
[Simulators](simulators.md#selected-origin-initialization).

CARLA frame data is generated by experiment preparation and cached separately. `CarlaDataset`
returns `Unavailable` for that generated evidence. See
[CARLA recipe types](../reference/python-api.md#avsectesterdatasetscarla) and
[the preparation workflow](experiments.md#prepare-and-execute-attacks).

## NuRec recordings

`NuRecDataset` reads the archives selected by
[dataset configuration](../reference/configuration.md#dataset). Recursive dataroot discovery
uses path order. An explicit `usdz_paths` list supplies the archives directly. Scenario
identities are native clip identifiers rather than filesystem paths.

Decision frames use the configured `time_step`. Ego and actor poses interpolate within recording
support and do not extrapolate. An actor outside its recorded support is absent. Camera
timestamps describe recorded image frames and are distinct from the decision timeline. Use
`camera_timestamps` when aligning video labels and `camera_geometry` for the optical model and
rig-from-camera transform.

`FrameData.sensor_references` retains the native `camera_id`. Model-visible name changes belong
to the [simulator's camera_aliases](simulators.md), not the dataset. `Dataset` camera and
trajectory methods take `scenario_id`. Their signatures and calibration constraints are in the
[NuRec API](../reference/python-api.md#avsectesterdatasetsnurec).

The public `read_scene_mesh` function reads world-coordinate mesh vertices and triangle faces
without selecting a camera. `NuRecDataset.scene_mesh` and the simulator share that reader. Depth
and ground contact are [simulator behavior](simulators.md#mesh-depth).

## nuScenes recordings

`NuScenesDataset` exposes scene tokens, recorded keyframe timelines and stable actor instance
IDs. It retains annotated categories and full extents. Sensor references use the configured
native camera name, such as `CAM_FRONT`.

`RecordedReplaySimulator` reads these references. Driving commands do not change recorded
motion. Configure its model-visible sensor names through [simulator aliases](simulators.md). The
[nuScenes API](../reference/python-api.md#avsectesterdatasetsnuscenes) defines source options.

## Semantic maps

`Dataset.scenario_map` returns `ScenarioMap` or an `Unavailable` value with a reason.
The base implementation provides no map. `ScenarioView.scenario_map` exposes it during
selection. Missing map evidence does not prevent other dataset operations. An attack decides
whether it can use that scenario.

| `Dataset` | Map source |
|---|---|
| NuRec | Aligned clipgt geometry from the scene archive |
| CARLA | Exported OpenDRIVE through the optional CARLA client package |
| nuScenes | **Not yet implemented.** See [nuScenes semantic maps](../development/TODO.md#nuscenes-semantic-maps). |

Maps contain lanes, drivable polygons, road boundaries, crosswalks, intersections, controls and
stop lines. Inspect `unavailable_layers` for missing layer evidence. An empty known layer and an
unavailable layer have different meanings. Geometry uses canonical world meters and
read-only arrays.

The [map record formats](../reference/python-api.md#avsectestermapsscenario_map) define
coordinate conventions and control pose references. The
[clipgt reader](../reference/python-api.md#avsectestermapsclipgt) and
[OpenDRIVE reader](../reference/python-api.md#avsectestermapsopendrive) define source
associations, classification rules and alignment limits.

A custom `Dataset` can construct the shared map records or return `Unavailable`. For an
OpenDRIVE source aligned with its canonical world frame, it can reuse `read_opendrive`.
Constructor path handling follows
[filesystem parameter rules](../reference/configuration.md#constructor-filesystem-parameters).

Maps are selection and evaluation evidence, not `AVStack` observations. An attack copies the map
information needed by its online phase into [segment user_data](attacks.md). Dynamic signal
states are recorded separately in
[WorldSnapshot](../reference/runtime.md#physical-and-model-visible-records).
